## La barra desaparece cuando una página lanza un error

Cuando ningún `error.tsx` captura un error de render, Next sustituye todo el layout raíz por su propia página de error ("This page couldn't load"), barra incluida. Renderiza también la barra en `app/global-error.tsx`; se reconecta y muestra el 500 y la petición que falló:

```tsx title="app/global-error.tsx"
'use client'
import { NextToolbar } from '@angelitolm/next-toolbar'

export default function GlobalError({ error }: { error: Error & { digest?: string } }) {
  return (
    <html lang="en">
      <body>
        <h1>Something went wrong</h1>
        <p>{error.digest ?? error.message}</p>
        <NextToolbar />
      </body>
    </html>
  )
}
```

Consulta [Empezar](./getting-started#4-mantenla-en-pantalla-cuando-una-página-falla).


## El modo de render dice Static pero en producción es dinámica

El modo desarrollo solo puede ver las APIs de petición y `force-dynamic`. Un fetch `no-store` o un segmento dinámico sin `generateStaticParams` parecen estáticos en desarrollo. NextToolbar detecta el caso no-store con las request insights y marca los segmentos dinámicos como `Static?`. Ejecuta `next build` para obtener la respuesta definitiva. Consulta [Modo de render](./render-mode).

## El modo de render muestra `?`

Una de estas:

- la página devolvió 4xx/5xx (el modo de render no se muestra para respuestas de error);
- la barra no está conectada al servidor de desarrollo: pasa el ratón por la versión de Next y comprueba **HMR socket**;
- tu app usa **Cache Components**, para los que Next no envía datos static/dynamic.

## El estado muestra `—`

El navegador no expone `responseStatus` (Safari), o la página vino de la caché de atrás/adelante del navegador.

## No hay tiempo del servidor, fetches ni profiler

Estás en una versión de Next anterior a 16.3, o `experimental.requestInsights` no está activado en `next.config`. El panel del segmento de tiempos muestra una pista cuando es así. Consulta [Configuración](./configuration).

## El indicador "N" de Next tapa la barra

Muévelo o desactívalo:

```ts
devIndicators: { position: 'top-right' } // or: devIndicators: false
```

## La lista de peticiones tiene demasiado ruido

Recoge peticiones de cada página, recarga y pestaña, además de route handlers y prefetches. Usa **Clear** en el profiler: conserva solo la petición de la página actual. Consulta [Profiler → Clear](./profiler#clear).

## Las peticiones borradas han vuelto

La barra oculta las peticiones que empezaron antes de que borraras, comparando el reloj del servidor de desarrollo con el del navegador. Con un servidor de desarrollo remoto cuyo reloj vaya atrasado, algunas pueden reaparecer.

## El patrón de ruta es incorrecto antes de Next 16.3

Sin request insights el patrón se reconstruye a partir de la URL y de `useParams()`. Un param cuyo valor coincide con un segmento estático (`/blog/blog`) puede etiquetarse mal. Next 16.3+ con request insights da el patrón exacto.

## La barra no aparece en un servidor de staging

Comprueba, en orden:

1. **La ruta de servidor está montada** en `app/api/next-toolbar/route.ts`. Sin ella nadie puede dejar entrar al navegador.
2. **`NEXT_TOOLBAR_SECRET` está definido en el proceso del servidor** y tiene al menos 16 caracteres. Se lee en tiempo de ejecución, así que reinicia `next start` después de cambiarlo. No debe ser una variable `NEXT_PUBLIC_`.
3. **La cookie está**: en DevTools → Application → Cookies, una cookie `next-toolbar` de este dominio con `path=/`, con exactamente el mismo valor.
4. **La ruta responde**: en la consola de DevTools, `fetch('/api/next-toolbar', { headers: { 'x-next-toolbar': '1' } }).then((r) => r.status)`. `404` significa que algo de lo anterior falla (o que un proxy bloquea `/api/next-toolbar`); `200` significa que la barra debería cargarse al recargar.
5. **`basePath`**: la ruta vive bajo él (`/docs/api/next-toolbar`), y el `path` de la cookie debe cubrirla.

## La lista de fetches en caché sale vacía en staging

La lista se lee de `.next/cache/fetch-cache` en el disco del servidor. Sale vacía en Vercel y otras plataformas serverless, con un `cacheHandler` propio, con un `distDir` propio, o antes de que alguna página haya cacheado un fetch. Los fetches con `no-store` nunca aparecen. Mira [Caché de fetch](./fetch-cache#en-un-servidor-de-staging).

## ¿Afecta a producción?

No. Fuera de `next dev` el componente devuelve `null`: sin render, sin socket, sin listeners, y las páginas no cargan el código de la barra. La única excepción es un servidor de staging que vuestro equipo active a propósito; mira [Staging](./configuration#staging-qa-self-hosted).

## ¿Funciona con `basePath`?

Sí, sin configuración. Consulta [Configuración → basePath](./configuration#basepath-y-assetprefix).

## ¿Funciona con el Pages Router?

No. NextToolbar está hecha para el App Router (depende de los hooks de `next/navigation` y de las peticiones RSC).
