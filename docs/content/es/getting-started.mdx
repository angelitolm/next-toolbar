## 1. Instala

```bash
pnpm add -D @angelitolm/next-toolbar
```

npm y yarn funcionan igual (`npm i -D …`, `yarn add -D …`). Instálala como dependencia de desarrollo: nunca se renderiza en producción.

## 2. Añádela al layout raíz

```tsx title="app/layout.tsx"
import { NextToolbar } from '@angelitolm/next-toolbar'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        {children}
        <NextToolbar />
      </body>
    </html>
  )
}
```

`NextToolbar` es un client component (el paquete incluye la directiva `'use client'`), así que puedes renderizarlo desde un layout que sea Server Component sin envolverlo.

Ponla en el layout **raíz** para que sobreviva a la navegación entre rutas y mantenga su conexión con el servidor de desarrollo.

## 3. `next.config.ts` recomendado

```ts title="next.config.ts"
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  // Next's own dev indicator sits bottom-left by default and overlaps the toolbar.
  devIndicators: { position: 'top-right' },
  // Next 16.3+ only: server timing, fetches, exact route patterns and the profiler.
  experimental: { requestInsights: true },
}

export default nextConfig
```

Las dos opciones son opcionales:

- Sin `devIndicators.position`, el indicador redondo "N" de Next queda encima del borde izquierdo de la barra. También puedes desactivarlo con `devIndicators: false`.
- Sin `requestInsights` (o antes de Next 16.3) la barra sigue mostrando estado, ruta, modo de render, tiempos del cliente, errores del cliente y versiones, pero no los tiempos del servidor, los fetches, la corrección del modo de render por no-store ni el profiler. Consulta [Compatibilidad](./compatibility).

## 4. Mantenla en pantalla cuando una página falla

<Callout type="warning" title="Recomendado">
  Si una página lanza un error al renderizar y ningún `error.tsx` lo captura, Next sustituye todo el layout raíz por su propia página de error ("This page couldn't load"), y la barra desaparece con él. Justo cuando más la necesitas.
</Callout>

Renderiza también la barra en `app/global-error.tsx`. Next usa ese archivo en lugar del layout raíz cuando un error no se captura, así que la barra vuelve con el status (500), la petición que falló y su error:

```tsx title="app/global-error.tsx"
'use client'
import { NextToolbar } from '@angelitolm/next-toolbar'

export default function GlobalError({ error }: { error: Error & { digest?: string } }) {
  return (
    <html lang="en">
      <body>
        <h1>Something went wrong</h1>
        <p>{error.digest ?? error.message}</p>
        <NextToolbar />
      </body>
    </html>
  )
}
```

Opcionalmente, un `app/error.tsx` (o uno por segmento de ruta, p. ej. `app/[locale]/error.tsx`) captura los errores *dentro* del layout raíz, de modo que el layout y su barra nunca desaparecen:

```tsx title="app/error.tsx"
'use client'

export default function Error({ error }: { error: Error }) {
  return <h1>Something went wrong: {error.message}</h1>
}
```

## 5. Ejecuta

```bash
pnpm dev
```

Abre cualquier página. La barra aparece como una franja a lo largo de la parte inferior de la ventana:

- pasa el ratón por cualquier segmento para ver los detalles;
- haz clic en el id de la petición (`# f9b45c`) para abrir el [profiler](./profiler);
- haz clic en el logo o en el botón de cerrar para minimizarla a un círculo.

## 6. Opcional: la ruta de servidor

Para revalidar rutas y tags desde la barra, y ver el nombre de las Server Actions en lugar de su id, añade un route handler:

```ts title="app/api/next-toolbar/route.ts"
export { GET, POST } from '@angelitolm/next-toolbar/server'
```

Solo responde en `next dev`. Consulta [Server Actions](./server-actions#revalidar-desde-la-barra).

## Producción

No tienes que hacer nada. En producción el componente no renderiza nada, no hace peticiones y nunca abre una conexión, y el código de la barra va en un chunk aparte que las páginas no cargan. No necesitas importarla de forma condicional. Para QA en un servidor de staging hay una excepción deliberada y opcional: mira [Staging](./configuration#staging-qa-self-hosted).
